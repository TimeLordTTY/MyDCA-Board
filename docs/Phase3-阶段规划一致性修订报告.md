# Phase3 阶段规划一致性修订报告

## 本次为什么修订

当前文档体系中存在阶段规划冲突：主设计文档和 Phase2 总结已经说明 Mobile H5 是 Phase2 历史交付、Phase3 起移动端长期形态切换为 Android 原生 App；但 `开发实施指南.md` 仍把 Phase3 定义为旧策略与建议阶段，并把复盘、回测放在 Phase4/5。为了避免后续开发入口混乱，本次将阶段路线统一为“对话优先，App 后置”。

- 主设计文档部分位置仍强调“原生 App 替代 Mobile H5”是 Phase3 第一交付物，未突出 Hermes 对话式记账优先级。

## 新阶段路线

- Phase 1：后端地基建设（已完成）。
- Phase 2：前端开发与行情增强（PC Web、Mobile H5 历史交付、行情/指标/定时任务高优先级闭环已完成；流水统计、债券行情、BOLL/KDJ 等仍作为增强项）。
- Phase 3：对话优先的草稿闭环与移动端基础。
- Phase 4：策略建议闭环。
- Phase 5：复盘 / 报表 / 优化。
- Phase 6：回测实验室与异步任务。

## Phase3 为什么对话优先

用户当前最需要的是快速把真实生活和投资动作进入“待确认草稿”，而不是先完成完整 App。Hermes 对话入口可以更早覆盖文本记账、截图记账、购买、赎回、转账、报销、退款等场景；服务端草稿和影响预览先落地后，后续 App 只需要承接更顺手的移动体验。

## App 为什么后置

Android 原生 App 是长期移动端形态，但完整 App 的工程量较大。如果把它作为第一交付物，会推迟最核心的记账闭环。因此 Phase3 前半段优先完成服务端草稿、Hermes 解析、影响预览、确认入账；App 在后半段承接草稿箱、今日待办、看板、支付通知监听和弹窗确认。

## 策略 / 复盘 / 回测如何顺延

- 原 Phase3 策略与建议顺延到 Phase4。
- 原 Phase4 复盘与优化顺延到 Phase5。
- 原 Phase5 回测实验室顺延到 Phase6，并保留异步任务管理边界。
- 策略建议阶段仍不自动交易，建议确认后也应生成订单草稿或交易草稿，再由用户确认。

## 后续开发入口

Phase3 后续开发应优先从以下入口进入：

- `draft_ledger_entry` 草稿表规划与 DDL 增量。
- `/api/v2/drafts` 草稿创建、查询、编辑、预览、确认、忽略接口。
- `/api/v2/ai/accounting/parse-text`、`parse-image`、`draft-from-intent`。
- 影响预览 payload 与幂等去重规则。
- Hermes 对话式记账 MVP。
- Android 原生 App 基础壳、草稿箱、今日待办和支付通知监听。
