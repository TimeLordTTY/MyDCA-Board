# v0.15 只读策略研究候选与证据门禁

策略实验室从已保存的回测历史中生成研究候选。`POST /api/v2/backtest-lab/runs/research` 接受 `runIds`（1 至 50 个不同的历史 UUID）及 `thresholds`。阈值包括 `minSampleDays`（1 至 3650 天）、`maxDrawdown`（0 至 1 的回撤幅度）、`minBaselineAnnualizedDelta`（-1 至 1）和 `minTradeCount`（0 至 100000）。省略整个 `thresholds` 时默认使用 180 天、0.30、0 和 3 次。请求中的部分阈值、非有限值或越界值会被拒绝。

服务按当前用户与家庭作用域读取历史文件，不重跑模拟器，不连接数据库。失败历史只列入 `excluded_runs`，不参与判定。成功记录按策略、版本和规范化参数分组；每组列出 run ID、数据集 SHA-256、日期区间、核心指标、相对基准差、阈值命中原因及警告。每条成功 run 都必须满足门禁；样本不足、交易次数不足或关键指标缺失标记 `EVIDENCE_INSUFFICIENT`，最大回撤超限或相对基准年化差不足标记 `DOES_NOT_MEET_CRITERIA`，全部满足才标记 `WORTH_FURTHER_RESEARCH`。数据集 hash 或日期区间不同的同组记录不能合并判断，证据状态标记不足。响应按固定规则排序，不含生成时间，也没有综合得分或单一“最佳策略”排名。

PC 页面复用历史记录选择，提供受控阈值输入，并显示每组状态、证据、原因和警告。界面明确提示“历史结果不代表未来表现；研究候选不是买卖或执行建议”。此接口只依赖历史仓库、当前用户和字段清洗服务；没有订单按钮，也不调用 OrderService、SettlementService 或 LedgerService 写接口。历史记录中的数据集文件名、CSV、路径和其他原始字段不进入研究报告。

验证：后端测试覆盖确定性与输入顺序、阈值等号边界、短样本、不同数据集、失败 run、owner scope、关键失败条件及无交易服务依赖；PC 类型检查与构建验证页面状态。部署本次代码不会迁移或连接生产数据库。
