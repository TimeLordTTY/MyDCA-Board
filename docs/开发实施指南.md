# 财富中枢系统 - 完整开发实施指南

**作者**：timelordtty

## 文档说明

本文档是《财富中枢系统完整设计方案.md》的实施指南，提供从零开始构建完整系统的详细步骤、验证方法和开发顺序。

**技术栈**：
- 后端：Java 17+ (Spring Boot 3.x) + MyBatis（不使用JPA）
- 前端：Vue 3 + TypeScript（PC: Element Plus, Mobile: Vant）
- Python：3.9+（行情、指标、策略、回测）
- 数据库：MySQL 8.0（已执行DDL脚本）
- 部署：Nginx（静态资源 + 反向代理），无Docker

**关键配置**：
- 包名：`com.timelordtty.dca`
- 接口版本：`/api/v2/`（v1为旧版本，当前为v2重构版本）
- 服务端口：8766
- 数据库：已配置并执行DDL
- 前端依赖：必须在 `web/` 根目录通过 npm workspaces 安装；前端构建脚本为 `web/build-web.bat`

**开发原则**：
- **Phase 1专注后端开发**，完成所有后端API和业务逻辑
- **Phase 2开始前端开发**，同时进行行情数据集成
- 每个阶段完成后进行验证，验证通过才能进入下一阶段
- 严格遵循设计方案，不引入中间件（无MQ、Redis、ES等）
- 本文档提供开发步骤和验证方法，不包含完整代码实现

**当前代码实现基线（2026-06-05）**：
- Phase 1 后端地基已完成：18 个 Model、18 个 Mapper、18 个 Service、15 个 Controller。
- Phase 2 前端/行情/指标/定时任务高优先级闭环已完成：PC 端核心页面、Mobile 端 5 个 Tab 与账户/产品/流水/订单轻量只读子页均已实现；流水统计功能已在 PC 流水页落地。
- 行情与指标已落地：`MarketDataScheduler`、`IndicatorCalculationTask`、`RealtimeQuoteCleanupTask`、`SnapshotGenerationTask`、`MmfInterestCalculationTask` 均已存在；BOLL/KDJ 扩展指标首版已接入指标表、Python 计算脚本、后端派生查询与 PC 持仓详情图表及最新指标摘要；债券/国债逆回购行情采集首版已覆盖 `BOND_REPO` 场内产品。
- 仍属于后续阶段：Phase3 图片记账 / 支付通知监听 / Android 真实联调，Phase4 策略建议完整闭环，Phase5 复盘 / 报表导出，Phase6 回测实验室 / 异步任务管理，以及普通债券/可转债行情、更多扩展指标等 Phase2 增强项。

#### 步骤1.1.4：实现JWT认证服务

**文件位置**：`backend/src/main/java/com/timelordtty/dca/security/`

**需要创建的类**：
1. `JwtTokenProvider.java` - JWT Token生成和验证
   - 方法：generateToken, getUsernameFromToken, validateToken
   - 配置：secret（密钥），expiration（过期时间，默认24小时）
2. `JwtAuthenticationFilter.java` - JWT认证过滤器
   - 从请求头`Authorization: Bearer <token>`提取token
   - 验证token并设置SecurityContext
3. `SecurityConfig.java` - Spring Security配置
   - 配置密码加密器（BCryptPasswordEncoder）
   - 配置SecurityFilterChain：公开`/api/v2/auth/**`，其他接口需要认证
   - 添加JwtAuthenticationFilter到过滤器链

**关键点**：
- JWT secret需要在配置文件中设置（生产环境必须修改）
- 使用Spring Security 6.x的新API（`requestMatchers`）
- Session策略设置为STATELESS（无状态）

**验证要点**：
- POST `/api/v2/auth/register` - 注册成功，返回token和用户信息
- POST `/api/v2/auth/login` - 登录成功，返回JWT token
- GET `/api/v2/users/me` - 使用Bearer token访问成功，返回当前用户信息
- 无token访问返回401 Unauthorized

#### 步骤1.2.2：创建账户实体与Mapper

**文件位置**：
- Model: `backend/src/main/java/com/timelordtty/dca/model/Account.java`
- Mapper: `backend/src/main/java/com/timelordtty/dca/mapper/AccountMapper.java`
- XML: `backend/src/main/resources/mapper/AccountMapper.xml`

**Account实体字段**：
- id, accountCode, accountName, accountType（CASH/POSITION/INCOME/EXPENSE/FEE/RECEIVABLE/LIABILITY）, accountKind（REAL/VIRTUAL）, virtualSubtype（仅VIRTUAL账户）, ownerUserId, ownerFamilyId, ownerType（PERSONAL/SHARED）, parentAccountId（父子账户关系）, fundUsage（SPENDABLE/RESERVED/INVESTABLE，仅REAL CASH叶子账户）, initialBalance, balance, reservedAmount, note, createdAt, updatedAt

**AccountMapper方法**：
- selectById, selectByOwner（按userId和familyId查询）, selectChildren（查询子账户）, selectLeafAccounts（查询叶子账户，用于记账校验）, insert, update, updateBalance, updateReservedAmount

**关键点**：
- `parentAccountId`用于父子账户关系（父账户=平台容器，子账户=真实信封余额）
- `fundUsage`仅对REAL CASH叶子账户生效
- 需要支持查询子账户和叶子账户

#### 步骤1.2.3：实现账户服务（应用层校验）

**文件位置**：`backend/src/main/java/com/timelordtty/dca/service/AccountService.java`

**关键业务规则（应用层必须校验）**：
1. VIRTUAL账户不允许设置parent_account_id
2. 子账户必须是REAL
3. 只有CASH类型的REAL账户允许形成父子层级
4. `ledger_posting.account_id`只允许引用叶子账户（禁止对父账户记账）

**AccountService方法**：
- createAccount（创建账户，包含上述校验）
- updateAccount（更新账户信息）
- getAccountTree（获取账户树形结构，父账户余额=Σ子账户余额）
- calculateParentBalance（计算父账户余额，聚合子账户）
- isLeafAccount（判断是否为叶子账户，用于记账校验）
- adjustBalance（调整余额，生成ADJUST类型流水）

**关键点**：
- 父账户不参与任何记账分录，禁止余额编辑
- 父账户展示余额 = Σ(子账户叶子余额)（仅展示层聚合）
- 余额调整必须生成ADJUST类型的ledger_txn和ledger_posting

**验证要点**：
- 创建VIRTUAL账户时设置parent_account_id应返回400错误
- 创建非CASH类型的REAL账户作为子账户应返回400错误
- 父账户余额 = 所有子账户余额之和
- 尝试对父账户创建ledger_posting应返回400错误

#### 步骤1.2.4：实现产品与账户管理Controller

**文件位置**：
- `backend/src/main/java/com/timelordtty/dca/controller/ProductController.java`
- `backend/src/main/java/com/timelordtty/dca/controller/AccountController.java`

**ProductController接口**：
- GET `/api/v2/products` - 获取产品列表（支持keyword、assetType、channel筛选）
- GET `/api/v2/products/{id}` - 获取产品详情
- POST `/api/v2/products` - 创建产品
- PUT `/api/v2/products/{id}` - 更新产品

**AccountController接口**：
- GET `/api/v2/accounts` - 获取账户列表（支持ownerType筛选，返回树形结构）
- GET `/api/v2/accounts/{id}` - 获取账户详情（父账户包含子账户列表和聚合余额）
- POST `/api/v2/accounts` - 创建账户（包含应用层校验）
- PUT `/api/v2/accounts/{id}` - 更新账户
- PUT `/api/v2/accounts/{id}/balance` - 调整账户余额（生成ADJUST流水）

**关键点**：
- 账户列表接口需要支持树形结构返回（父账户包含children数组）
- 父账户的balance字段在返回时计算为子账户余额之和
- 余额调整接口必须生成ADJUST类型的流水，不允许直接修改balance字段

#### 步骤1.4.2：实现订单服务

**文件位置**：`backend/src/main/java/com/timelordtty/dca/service/OrderService.java`

**OrderService核心方法**：
- createOrder（创建订单，支持组合支付）
  - 参数：fundingLines（数组，每个元素包含accountId和amount）, productId, orderType
  - 校验：Σ(fundingLines.amount) = requestedAmount（应用层校验）
  - 校验每个账户可用余额：`account.balance - account.reserved_amount >= fundingLine.amount`
  - 校验账户fund_usage（应用层校验）：
    - **EXPENSE订单**：source_account.fund_usage必须=SPENDABLE（专款禁止消费）
    - **BUY/SUBSCRIPTION订单（非逆回购）**：source_account.fund_usage必须=INVESTABLE（除非显式确认放开SPENDABLE）
    - **BOND_REPO订单（逆回购）**：忽略fund_usage限制，允许SPENDABLE/RESERVED/INVESTABLE（逆回购是现金增强工具，不是风险投资）
    - 但仍要严格禁止：RESERVED账户用于日常EXPENSE消费，RESERVED账户用于ETF/股票等风险投资
  - 创建订单记录（status=PENDING）
  - 写入order_funding_line表（每个fundingLine一行）
  - 分别增加各账户的`reserved_amount`（占用资金，不扣款，不生成流水）
  - **逆回购特殊处理**：如果product.asset_type=BOND_REPO，订单类型通过product判定（或新增order_type='BOND_REPO'），下单时只增加reserved_amount，不生成流水
- cancelOrder（取消订单）
  - 只能取消PENDING状态的订单
  - 查询order_funding_line，逐条释放各账户的`reserved_amount`
  - 删除order_funding_line记录（CASCADE自动删除）
  - 更新订单状态为CANCELLED
- getPendingOrders（获取待结算清单）
  - 查询status=PENDING的订单
  - 按expectedConfirmDate排序
  - 关联查询order_funding_line，返回资金来源明细

**关键业务规则**：
1. 订单创建时只增加`reserved_amount`，不生成真实流水
2. `reserved_amount`增加时，`balance`不变
3. 可用购买力 = `balance - reserved_amount`
4. 投资类订单（BUY/SUBSCRIPTION，非逆回购）默认从INVESTABLE账户，如需从SPENDABLE账户需要显式确认
5. **逆回购订单（BOND_REPO）**：
   - 允许从任意fund_usage账户（SPENDABLE/RESERVED/INVESTABLE）作为资金来源
   - 下单时只增加reserved_amount，不生成流水
   - 到期确认时：释放reserved_amount，生成利息流水（CASH DEBIT + INCOME CREDIT）
   - 不生成持仓POSITION（逆回购是现金增强工具，不是投资）

**验证要点**：
- 创建订单后，`reserved_amount`增加，`balance`不变
- 可用余额不足时创建订单应返回400错误
- 取消订单后，`reserved_amount`减少
- 待结算清单正确显示PENDING订单

### Phase 1.5: 持仓计算模块（3-5天）

#### 步骤1.5.1：实现持仓计算服务

**文件位置**：`backend/src/main/java/com/timelordtty/dca/service/HoldingService.java`

**HoldingService核心方法**：
- calculateHoldings（计算实时持仓）
  - 查询所有持仓类分录（account_type=POSITION）
  - 按product_id分组汇总
  - 计算总份额、总成本、平均成本
  - 获取最新净值计算市值和未实现盈亏
- calculateHoldingByProduct（计算单个产品持仓）
- getHoldingHistory（获取持仓历史曲线）

**持仓计算公式**：
- 总份额 = Σ(买入份额DEBIT) - Σ(卖出份额CREDIT)
- 总成本 = Σ(买入成本DEBIT) - Σ(卖出成本扣减CREDIT)
- 平均成本 = 总成本 / 总份额
- 市值 = 总份额 × 最新净值
- 未实现盈亏 = 市值 - 总成本

**成本方法**（MVP默认平均成本法）：
- 买入：增加份额和成本
- 卖出：按平均成本计算成本扣减 = 卖出份额 × 平均成本

**关键点**：
- 持仓计算基于`ledger_posting`实时计算，不依赖快照
- 支持按用户、按产品查询
- 需要从market_nav表获取最新净值（Phase 2实现）

#### 后端实现

**当前实现文件**：

**建议接口**：
- [x] GET `/api/v2/ledger/stats/summary`：总收入、总支出、净流入、交易笔数、日均支出、最大单笔支出。

- [x] GET `/api/v2/ledger/stats/breakdown`：按 `CATEGORY_L1|CATEGORY_L2|ACCOUNT|PARENT_ACCOUNT|TXN_TYPE` 拆分统计。

**统一筛选参数**：
- `startDate`、`endDate`：日期范围，默认本月。
- `txnTypes`：交易类型多选。
- `accountIds`：叶子账户多选。
- `parentAccountIds`：父账户多选，后端展开为子账户统计。

- `includeTransfer`：是否包含转账，默认 false。
- `scope`：`PERSONAL|FAMILY`，复用当前权限模型。

**统计口径**：
- 默认只统计 `status=CONFIRMED` 且未撤销流水。
- 转账默认不计入收入/支出，可单独统计资金流转。
- 投资买入/赎回默认不混入生活收支，可作为投资现金流单独统计。
- 多分录交易按业务流水去重，避免借贷两边重复计入。
- 父账户统计由叶子账户分录汇总，父账户本身不参与记账。

**需要创建的脚本**：
1. `generate_suggestions.py` - 生成建议
   - 参数：user_id, product_ids（可选，不传则查询所有关注产品）

**完整配置内容**（已保存在`config/nginx/wealth-hub.conf`）：
```nginx
server
{
    listen 80;
    listen [::]:80;
    server_name www.timelordtty.cn;
    index index.html index.htm default.htm default.html;
    root /www/wwwroot/wealth-hub/backend;
    include /www/server/panel/vhost/nginx/extension/wealth-hub-1/*.conf;
    
    # PC端前端静态资源
    location /wealth-hub {
        alias /www/wwwroot/wealth-hub/frontend/dist/wealth-hub;
        index index.html;
        try_files $uri $uri/ /wealth-hub/index.html;
    }
    
    # Mobile端前端静态资源
    location /wealth-hub-mobile {
        alias /www/wwwroot/wealth-hub/frontend/dist/wealth-hub-mobile;
        index index.html;
        try_files $uri $uri/ /wealth-hub-mobile/index.html;
    }
    
    # API反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8766;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Host $host:$server_port;
        proxy_set_header X-Scheme $scheme;
        proxy_connect_timeout 30s;
        proxy_read_timeout 86400s;
        proxy_send_timeout 30s;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    access_log  /www/wwwlogs/wealth-hub-1.log;
    error_log  /www/wwwlogs/wealth-hub-1.error.log;
}
```

**关键点**：
- PC端：`http://www.timelordtty.cn/wealth-hub` → `/www/wwwroot/wealth-hub/frontend/dist/wealth-hub`

## Phase3 文本记账解析 MVP 验证与加固说明（2026-06-11）

- `parse-text` 首版继续采用规则解析，不接真实大模型或外部 API；结果只作为候选 intent。

## Phase3 草稿影响预览增强说明（2026-06-17）

- `DraftPreviewDTO` 已扩展 `accountName`、`accountType`、`fundUsage`、`impactDirection`、`accountDelta`、`willCreateLedgerTxn`、`willCreateOrder`、`willCreateSettlement`、`willAffectHolding` 和 `warnings`。
- `DraftLedgerEntryService.previewDraft` 只生成和保存 `preview_payload_json`，不得写 `ledger_txn`、`ledger_posting` 或修改账户余额。
- `accountId` 必须通过当前用户/家庭可见的 active REAL 账户校验；不可见或不可用账户不得确认。

### 草稿影响预览验证加固说明（2026-06-17）

- 预览阶段必须使用权限过滤后的 active REAL 账户生成影响预览。
- `accountId` 不存在、已停用、非 REAL 或当前用户/家庭不可见时，必须返回清晰 message / warnings，并禁止确认。
- `EXPENSE` 的 `accountDelta` 必须为负数，`INCOME` 的 `accountDelta` 必须为正数；unsupported txnType 必须保持 `impactDirection=NONE`、`accountDelta=0`、`willCreateLedgerTxn=false`。
- preview 不得调用 `QuickEntryService`，不得写 `ledger_txn`、`ledger_posting` 或修改账户余额。

## Phase3 今日待办与确认入口说明（2026-06-17）

- 新增 `GET /api/v2/todos/today`：返回当前用户或当前家庭可见的今日待办摘要。
- 首版待办来源只包含 `draft_ledger_entry.status = DRAFT` 的草稿；待结算和策略建议暂未接入，接口返回 0。
- 今日待办接口只读，不得创建、确认、忽略或更新草稿，不得写 `ledger_txn`、`ledger_posting`，不得修改账户余额、持仓成本或订单状态。
- PC 端仪表盘展示“今日待办”卡片，草稿待办点击后跳转到草稿箱，由用户在草稿箱查看 preview 后手动确认。
- shared 层通过 `todoApi.getTodayTodos()` 暴露接口，`TodayTodo` / `TodoItem` 类型可供 PC、移动端和后续通知摘要复用。
- 后续扩展待结算和策略建议时，必须继续保持“发现待办”和“确认执行”分离；首页入口只能导航，不应直接执行入账、结算或交易动作。

### 今日待办验证加固说明（2026-06-17）

- `TodoService` 必须使用 `countVisibleByStatus(userId, familyId, "DRAFT")` 返回真实草稿总数，并使用 `selectVisibleList(userId, familyId, "DRAFT", 0, 20)` 控制首页明细数量。
- `TodoController` 必须从当前登录用户读取 `userId` / `familyId`，不得接受前端传入的用户或家庭 ID 覆盖权限边界。
- `/drafts?draftId=xxx` 只用于草稿箱定位和选中草稿，不得自动生成 preview、自动确认或写入正式账本。
- 如果目标草稿不在当前筛选结果中，前端只提示用户切换筛选条件；不得绕过草稿列表权限边界额外拉取不可见数据。
- 待结算和策略建议接入前继续返回 0，并在前端文案中说明“暂未接入”，避免用户误解为已完成业务闭环。

**Android 通知候选生成草稿验证加固（2026-06-23）**：
- rawInput 构造只读取脱敏摘要、来源、标题和金额，不读取或传递完整 `rawText`。

- Android 侧创建草稿后仍不自动 preview 或 confirm；正式入账仍必须在草稿箱中由用户手动二次确认。


**Android 草稿编辑与账户补全首版（2026-06-24）**：
- Android 草稿箱在详情区域提供 DRAFT 草稿编辑能力，字段包括 `txnType`、`amount`、`note`、`accountId` 和 `accountNameHint`。

- `accountId` 是后端真实账户 ID，首版手动输入且必须为正整数；`accountNameHint` 只用于提示，不作为确认依据。

- confirm 仍由用户手动触发，且必须满足当前草稿为 DRAFT、preview 匹配当前草稿、`confirmSupported=true`。
